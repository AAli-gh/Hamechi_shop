# بازارچه (Bazarcheh)

فروشگاه اینترنتی فارسی و راست‌به‌چپ (RTL) برای کالاهای دیجیتال، مد و پوشاک، خانه و آشپزخانه،
آرایشی و بهداشتی، ورزشی و کودک. شامل ویترین فروشگاه برای مشتری و پنل مدیریت.

## امکانات

**فروشگاه**

- دسته‌بندی چندسطحی، جستجوی فارسی و فیلترها
- صفحه‌ی محصول با تنوع (رنگ، سایز و ...)، مشخصات فنی و نظرات کاربران
- مقایسه‌ی محصولات و لیست علاقه‌مندی‌ها
- سبد خرید، ثبت سفارش با آدرس‌های ذخیره‌شده و روش‌های ارسال، کد تخفیف
- پیگیری سفارش، فاکتور، درخواست لغو و مرجوعی
- اطلاع‌رسانی موجود شدن کالا با ایمیل
- وبلاگ

**پنل مدیریت**

- محصولات (تصاویر، تنوع‌ها، مشخصات) و دسته‌بندی‌ها
- سفارش‌ها و موجودی انبار
- تخفیف‌ها، بنرها، وبلاگ و خبرنامه
- گزارش‌ها و درخواست‌های اطلاع از موجودی

## فناوری‌ها

| بخش | ابزار |
|---|---|
| مخزن | pnpm workspaces، Node.js 24، TypeScript 5.9 |
| API | Express 5، Zod، ساخت با esbuild |
| دیتابیس | PostgreSQL + Drizzle ORM |
| قرارداد API | OpenAPI + Orval (تولید خودکار هوک‌ها و اسکیماهای Zod) |
| فروشگاه | React 19، Vite، wouter، TanStack Query، Tailwind، shadcn/ui |
| احراز هویت | Clerk |

## ساختار پروژه

```
artifacts/
  api-server/      سرور API (مسیرها در src/routes، منطق مشترک در src/lib)
  koodakland/      فروشگاه و پنل مدیریت (src/pages و src/pages/admin)
  mockup-sandbox/  محیط ساخت ماکاپ‌های رابط کاربری
lib/
  api-spec/        openapi.yaml — مرجع اصلی API
  api-client-react/  هوک‌های تولیدشده برای React
  api-zod/         اسکیماهای Zod تولیدشده
  db/              اسکیمای دیتابیس و اسکریپت داده‌ی نمونه
scripts/           اسکریپت‌های کمکی
```

## راه‌اندازی

پیش‌نیازها: Node.js 24، pnpm و یک دیتابیس PostgreSQL.

```bash
pnpm install
```

متغیرهای محیطی:

| متغیر | توضیح |
|---|---|
| `DATABASE_URL` | آدرس اتصال PostgreSQL (الزامی) |
| `PORT` | پورت سرور (الزامی) |
| `BASE_PATH` | مسیر پایه‌ی فروشگاه (برای اجرای فروشگاه الزامی) |
| `CLERK_SECRET_KEY`، `CLERK_PUBLISHABLE_KEY` | کلیدهای Clerk |
| `SMTP_URL`، `MAIL_FROM`، `PUBLIC_SITE_URL` | اختیاری — برای ایمیل‌های موجود شدن کالا |
| `CORS_ORIGINS` | اختیاری — فقط اگر فروشگاه از دامنه‌ی دیگری سرو شود |

ساخت جدول‌ها و پر کردن دیتابیس با داده‌ی نمونه‌ی فارسی:

```bash
pnpm --filter @workspace/db run push
pnpm --filter @workspace/db run seed
```

> ⚠️ دستور `seed` جدول‌های کاتالوگ (محصولات، دسته‌بندی‌ها، سفارش‌ها، سبدها) را پاک می‌کند.

اجرای سرور API و فروشگاه (در دو ترمینال جدا):

```bash
pnpm --filter @workspace/api-server run dev
pnpm --filter @workspace/koodakland run dev
```

### توسعه‌ی محلی بدون Clerk

با `DEV_AUTH=true` روی API و `VITE_DEV_AUTH=true` روی فروشگاه، Clerk دور زده می‌شود و همه‌ی
درخواست‌ها به‌عنوان یک کاربر ادمین ثابت در نظر گرفته می‌شوند. این تنظیمات در
`NODE_ENV=production` نادیده گرفته می‌شوند.

## دستورهای مفید

| دستور | کاربرد |
|---|---|
| `pnpm run typecheck` | بررسی تایپ همه‌ی پکیج‌ها |
| `pnpm run build` | بررسی تایپ و ساخت همه‌ی پکیج‌ها |
| `pnpm --filter @workspace/api-spec run codegen` | تولید دوباره‌ی هوک‌ها و اسکیماها از OpenAPI |

## تست‌ها

تست‌های API روی یک سرور در حال اجرا و دیتابیس seed‌شده اجرا می‌شوند و در دیتابیس می‌نویسند؛
هرگز آن‌ها را روی دیتابیس production اجرا نکنید.

```bash
pnpm --filter @workspace/db run seed
DEV_AUTH=true RATE_LIMITS=off PORT=8090 pnpm --filter @workspace/api-server run dev
```

و در ترمینال دیگر:

```bash
DATABASE_URL=... pnpm --filter @workspace/api-server run test
```

با `API_URL` (پیش‌فرض `http://127.0.0.1:8090`) می‌توان تست‌ها را به سرور دیگری فرستاد.

## نکات معماری

- **API از روی `openapi.yaml` ساخته می‌شود.** اول این فایل را تغییر دهید، بعد codegen را اجرا کنید
  و بعد کد را بنویسید.
- **قیمت‌ها سمت سرور محاسبه می‌شوند:** قیمت فعلی محصول، قوانین تخفیف و هزینه‌ی ارسال هنگام ثبت
  سفارش حساب می‌شوند و کلاینت فقط نمایش می‌دهد.
- **تنوع محصول:** در محصولات دارای تنوع، موجودی روی تنوع‌ها نگه‌داری می‌شود و `products.stock`
  مجموع آن‌هاست.
- **جستجوی فارسی:** چون PostgreSQL پیکربندی متن فارسی ندارد، حروف و ارقام عربی/فارسی، نیم‌فاصله و
  فاصله‌ها در هر دو طرف مقایسه یکسان‌سازی می‌شوند.
- **تصاویر** هنگام آپلود به WebP تبدیل و با پارامتر `?w=` در اندازه‌های مختلف (با کش روی دیسک)
  سرو می‌شوند.

## محدودیت‌های فعلی

- **درگاه پرداخت پیاده‌سازی نشده است:** سفارش‌ها با وضعیت `pending` ثبت می‌شوند.
- **پنل پیامک نمایشی است** و به سرویس پیامکی وصل نیست.
- بدون `SMTP_URL`، اعلان‌های موجود شدن کالا در حالت انتظار می‌مانند.
